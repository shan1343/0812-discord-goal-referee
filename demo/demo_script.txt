Discord Goal Referee — 45초 Hero Demo (D 소유)

촬영 전 통과 조건
- Discord 테스트 서버 #project-room과 배포된 HTTPS 웹 URL이 열린다.
- happy_path 및 deadline_conflict fixture가 /seed_demo에서 선택된다.
- /assign, /reassign, /confirm, /progress, /files가 실제 또는 명시된 demo fallback으로 동작한다.
- owner, reason, evidence, confidence, blocker, alternative가 역할 카드에 보인다.
- bot token/API key, 실제 개인정보, DM 또는 허용되지 않은 채널이 화면에 없다.
- 브라우저 알림, 개인 프로필, 다른 탭을 닫고 1280×720 이상으로 녹화한다.

00–05초 — 문제와 Goal
[화면] Discord #project-room과 “15:30까지 작동 데모” Goal을 한 화면에 둔다.
[멘트] “대화에 흩어진 약속과 파일을, 확인 가능한 역할과 진행률로 바꿉니다.”

05–12초 — 대표 입력
[동작] /seed_demo happy_path 실행. 가짜 대화와 첨부파일이 들어온 장면을 보여준다.
[멘트] “허용된 프로젝트 채널의 가짜 대화와 파일만 불러옵니다.”

12–20초 — 역할 제안
[동작] @GoalReferee 역할 나눠줘 또는 /assign 실행.
[멘트] “AI가 담당자를 확정하는 대신, 근거가 있는 역할안을 제안합니다.”

20–29초 — 설명 가능한 카드
[화면] 카드 하나의 owner/reason/evidence/confidence/alternative를 순서대로 가리킨다.
[멘트] “누가 맡는지뿐 아니라 이유, 원문 근거, 신뢰도와 대안까지 함께 봅니다.”

29–36초 — 틀린 배정 수정
[동작] deadline conflict 추가 후 /reassign. 변경 전후 owner와 blocker/change_reason을 보여준다.
[멘트] “마감 충돌을 넣으면 후보를 제외하고 변경 이유를 남깁니다.”

36–42초 — 진행률과 파일
[동작] /progress, 이어서 /files 실행. review_pending, 누락 파일, 최신본/checksum을 보여준다.
[멘트] “메시지 양이 아니라 완료조건, 파일, 테스트와 승인 근거로 진행률을 계산합니다.”

42–45초 — 사람 확인과 배포
[동작] Confirm 버튼 위에서 멈춘 뒤 HTTPS 웹 대시보드 URL을 보여준다.
[멘트] “최종 배정과 완료는 사람이 확인하며, 전체 근거는 배포된 웹에서 봅니다.”

실패 시 백업 경로
- Bot/API 오류: 오류 화면을 숨기지 말고 “demo fixture fallback” 배지를 1초 보여준 뒤 같은 흐름을 계속한다.
- Discord 지연: 사전 녹화한 seed 결과 화면에서 /assign부터 진행한다.
- 배포 장애: 배포 실패를 PASS로 표기하지 않는다. 백업 영상은 시연 연속성만 보장하며 Gate 1/7을 대체하지 않는다.
- 45초 초과: 설명을 줄이고 필수 장면 7개는 삭제하지 않는다.
